Making a React App Findable: Real HTML Pages Before JavaScript Runs

How I made a React scorekeeper visible to search: real HTML guides generated at build time, private app routes marked noindex and structured data that matches the page.

Tags

  • SEO
  • React
  • Vite
  • Static Generation
  • Structured Data

Published November 24, 2026.

A scorekeeper is a React app, and a React app starts life as an empty page. Search engines can run JavaScript, but a page that is only a blank shell until scripts finish is slow to understand, and it tells readers nothing if scripts fail. So the public side of the Hazari scorekeeper is plain HTML.

Two kinds of page

  • Public pages: the home page, guides on scoring, rules, card points and live sharing, plus About, Privacy and Contact, each in English and Bangla. They are real HTML before any JavaScript runs.
  • App pages: the saved games, scoring screens and shared scoreboards. They are private, marked noindex, and left out of the sitemap.

Generated at build time

The public pages are written from translated source files by a build script, which also produces the robots file, the sitemap and the hosting configuration. Editing a guide means editing one source file and rebuilding. Public pages do not load React, the database, or the cloud code, and their initial JavaScript is held under a 15 KB limit by a build check.

Each page earns its place

  • A unique title, description and H1.
  • Its own canonical address.
  • Reciprocal English and Bangla alternates so each language points to the other.
  • Social preview metadata.
  • Structured data that describes what is actually on the page. There are no invented reviews or ratings.

Letting crawlers read the noindex

The robots file allows crawling. That sounds backwards, but a crawler can only obey a noindex instruction if it is allowed to fetch the page and read it. The sitemap lists only public pages, and never a game identifier or a shared link.

Checks that fail the build

The build verifies the content, metadata, language links, structured data hashes, sitemap, manifest and the JavaScript limit. Browser tests load every public page with JavaScript disabled, in both languages and both themes, and check that real content is there.

What it does not do

None of this guarantees a ranking. It removes technical obstacles and makes the pages honest and readable. The rest depends on whether people find the pages useful, and on time.
